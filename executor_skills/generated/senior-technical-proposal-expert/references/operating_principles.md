# Operating Principles

## Principle 1: Expert Identity Before Task Vocabulary

One sentence: Use the senior expert's operating frame first; treat task-specific terms as examples or specializations, not as the skill identity.

Use when: Use on every activation of this skill.

Failure mode: Overfitting the response to a familiar task noun instead of solving the deeper work type.

## Principle 2: Evidence Must Become Decision Control

One sentence: Data, validation, costs, governance, and audit details should change decisions, not merely decorate the proposal.

Use when: Use whenever the deliverable proposes adoption, promotion, publication, or production-readiness.

Failure mode: Listing risks without gates, thresholds, owners, or consequences.

## Principle 3: Fine-grained Checks Serve The Expert Model

One sentence: Atomic cards should make senior judgment executable at the paragraph, table, threshold, and artifact level.

Use when: Use before finalizing any technical proposal.

Failure mode: Turning rubrics into a flat checklist without preserving expert-level reasoning.
